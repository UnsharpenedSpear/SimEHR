What is an EHR & What Problems Does This Solve?

Real-world clinical challenges addressed by the system

🔒 Protecting Sensitive PHI

Standard databases store patient SSNs and names in plaintext or only use disk encryption. If database dumps or logs leak, records are exposed. This system encrypts sensitive fields individually with AES-256-GCM.

🔍 Fast Search on Encrypted Data

Strong encryption produces random ciphertext, which normally breaks exact-match lookups. We use deterministic HMAC blind indexes so patient searches by SSN or phone execute in $O(1)$ time without decrypting the whole database.

🏥 Clinical Safety & Real-Time Flow

Prevents adverse drug interactions via Clinical Decision Support (CDS), prevents doctor double-booking, and coordinates patient/specimen transport using real-time WebSockets and QR scanning.

Field-Level Encryption & Deterministic Blind Indexing

How sensitive patient data is protected without losing instant search performance

🔐 AES-256-GCM Field Encryption

Sensitive fields (SSN, Legal Name, Phone, Email, Address) are encrypted before reaching the database:

  • Random 12-byte IV: Every field gets a unique random initialization vector.
  • 16-byte GCM Tag: Verifies ciphertext integrity and detects tampering.
{
  "mrn": "MRN-MAIN-202609-00042",
  "ssn": {
    "ciphertext": "8f3b2a19...",
    "iv": "d4e5f6a7...",
    "tag": "1a2b3c4d..."
  }
}
⚡ HMAC-SHA256 Blind Indexing

Because AES-GCM ciphertext is randomized, exact searching would normally require scanning and decrypting all records.

normalize(input) = lowercase & strip non-alphanumerics

blindIndex = HMAC_SHA256(normalizedText, BLIND_INDEX_SALT)

The deterministic hash is stored in a MongoDB B-Tree index, enabling $O(1)$ sub-millisecond lookups by SSN, phone, or email with zero plaintext leakage.

Clinical Orders & 7 Polymorphic Discriminators

Modeling diverse clinical orders efficiently in MongoDB

🧬 Why Mongoose Discriminators?

Orders share common lifecycle fields (patientId, encounterId, status, priority, orderDate) but require specialized schemas per order type.

Discriminators allow 7 distinct order schemas to share a single MongoDB collection for fast indexed queries.

// All queryable via OrderModel.find()
OrderModel.discriminator('LabOrder', LabOrderSchema);
OrderModel.discriminator('ImagingOrder', ImagingSchema);
OrderModel.discriminator('NursingOrder', NursingSchema);
📦 The 7 Specialized Discriminators
  • LabOrder: Specimen types, test panels, reference ranges.
  • ImagingOrder: Modality (X-Ray, CT, MRI), contrast flags.
  • NursingOrder: Shift care plan tasks and frequency.
  • ConsultOrder: Specialty department referrals.
  • DietaryOrder: Clinical nutrition instructions.
  • MinorProcedure & SurgicalProcedure: Bedside and OR procedure tracking with clinician PIN authorization.

Prescriptions & Clinical Decision Support (CDS)

Real-time interaction checker preventing adverse drug events (ADEs)

💊 RxNorm Formulary

Prescriptions use standard RxNorm semantic clinical drug codes with structured dosage, route, and frequency instructions.

⚠️ Automated CDS Checks

Before submitting an order, the engine automatically checks:

  • Drug-Drug: Cross-checks active meds (e.g. Warfarin + NSAIDs).
  • Drug-Allergy: Checks ingredients vs allergy list.
  • Duplicate Therapy: Flags overlapping drug classes.
🛡️ Clinical Override & Dispense

If a severe interaction is detected, the UI prompts the physician for a documented clinical override reason. Once signed, orders route directly to the Pharmacy worklist for verification and dispensing.

Real-Time Hospital Dispatch & SLA Tracking

Porter task coordination, physical QR verification, and automated SLA timers

🔄 Finite State Machine (FSM)
PENDING ➔ ASSIGNED ➔ IN_TRANSIT ➔ ARRIVED ➔ COMPLETED
  • Task Dispatch: Requests for blood specimen transport, wheelchair escorts, or emergency equipment.
  • Physical QR Verification: Porters scan patient wristbands or specimen labels to verify chain of custody.
  • Socket.IO Broadcasting: Department boards (Lab, Radiology, ER) receive live task updates instantly.
⏱️ Background SLA Sweeper

A background worker runs every 60 seconds inspecting active dispatch tasks.

If a STAT task exceeds target response time (e.g., >20 mins), the system emits an sla:breached WebSocket alert with audio-visual notifications on clinician dashboards.

Appointments, Scheduling & Itemized Invoicing

Preventing calendar conflicts and automating financial settlement

📅 Conflict-Free Scheduling
  • Double-Booking Protection: MongoDB compound unique indexes on (providerId, facilityId, startTime) prevent overlapping bookings.
  • Appointment Flow: SCHEDULED ➔ CHECKED_IN ➔ IN_CONSULTATION ➔ COMPLETED.
  • Tracks cancellations and no-shows for clinic scheduling analytics.
💳 Consolidated Invoicing & Billing
  • Automatically aggregates all billable items from an encounter: doctor visit fees, bed charges, lab panels, radiology exams, and dispensed pharmacy drugs.
  • Calculates taxes, insurance copayments, and outstanding balances.
  • Records payments (Cash, Credit Card, Insurance Direct) and generates itemized printable invoice receipts.

Tamper-Evident SHA-256 Hash-Chained Audit Trail

Cryptographic ledger enforcing audit non-repudiation for HIPAA § 164.312(b)

🔗 How Hash Chaining Works

Every audit entry calculates a SHA-256 hash incorporating its own event data plus the hash of the preceding entry:

EntryHash[n] = SHA256(
  EntryHash[n-1] +
  Timestamp +
  ActorID +
  Action +
  ResourceID +
  FacilityID +
  MetadataDigest
)

If anyone alters an old record or deletes a log row in MongoDB, the entire downstream hash sequence breaks immediately.

🛡️ Built-In Verification API

Endpoint: GET /api/v1/audit/verify

  • Iterates chronologically through the entire audit collection.
  • Recalculates all cryptographic hashes in sequence.
  • Confirms 100% data integrity or pinpoints the exact corrupted entry.
